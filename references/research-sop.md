# Research SOP
> Module 3 of 4. Execute the series selected by `references/classification-routing.md`, under `SKILL.md` integrity rules. Product, competitive actor and transaction diligence are **alternative primary protocols**, with selective cross-calls. Do not execute every series merely because it is present.
## Shared research kernel
1. `Resolve → Scope / Coverage Plan → Acquire → Verify → Analyze → Benchmark → Test Counter-theses → Synthesize Findings → Recommend / Revalidate`. Use the P0–P3 queue only for sequencing, never removal of in-scope mandatory domains.
2. `Remote` maps published evidence to evaluation tracks, not personal tests. `Hands-on` requires supplied primary measurements/logs; `Internal` requires authorized internal records and provenance. Preserve actual Evidence Access separately.
3. Build `Source → Evidence → Finding → Recommendation` lineage with original origin IDs, conflicting/counter evidence, method and subject/date fit. Do not convert claims or signals to validated outcomes.
4. Apply the appropriate subject-specific coverage matrix and both completion gates from `SKILL.md`. Structured IDs, finding/coverage/source registers and report compilation belong to `references/output-contract.md`.

## Product evaluation and five-track test protocol
### Product identity and official visual
Resolve Brand / Family / Model / Generation / SKU / Variant / Region before visual or specification collection.

Retrieve a suitable official high-resolution image by default, preferring official asset/media library → press/newsroom → original product-page asset. Record first-party URL/Source ID, origin, product/generation/visible-variant match, date and required attribution. Never substitute unofficial or generated images; otherwise record `Unavailable`.
### Product fact sheet and specification matrix
Resolve and record when available:
- Brand / Family / Model / Generation / SKU / Variant / Region; Launch Date; MSRP / Current Street Price / Price Observation Date; Firmware / OS / App / Software Version; Core Specifications / Hardware Architecture
- Dimensions / Weight / Materials / Finish where published; Interface / Connectivity / Protocol support; Power / Battery / Charging; Sensors / Compute / Memory / Storage where applicable
- Audio / Display / Camera / RF / Mechanical parameters as category-appropriate; Environmental / durability ratings where published; Software / AI capabilities; Accessories / Bundles; Subscription / Services; Warranty / Service
- Regional Differences; Product Role / Positioning; Target Markets (`Consumer` / `Professional` / `Enterprise` / `Government` / `Defense`) with evidence basis; Buyer / Procurement Decision Authority / End User Roles
- Industry Verticals / Usage Scenarios / Deployment Contexts, when material
Build a structured Product Specification Matrix by default. Suggested columns:
| Parameter | Value | Unit | SKU / Region / Version | Evidence Status | Source ID |
|---|---|---|---|---|---|
Use official specifications as the primary source. Include the full official specification set when reasonably accessible, including lower-materiality parameters that may still matter during manual review. Mark unresolved or unpublished fields `Unknown`. Keep third-party measurements separate from official specifications.

Classify each field as Official Fact / Third-party Fact / Unknown.
### Claims and change analysis
Manufacturer Claim = Hypothesis Input.

Classify manufacturer claims as Performance / Experience / Workflow / AI-Software / Ecosystem / Durability-Lifecycle / Marketing-Hard-to-verify. For generations apply `Changed → Measurable? → Perceptible? → Decision-relevant?`.
### Segment / JTBD / scenario
Define:
- Evidenced target-market labels vs potential-market hypotheses, with separate source / Confidence status; Economic Buyer / Procurement Owner / Decision Makers / End Users (distinguish purchasing authority from product operation)
- Industry Vertical / Deployment Constraints; Primary Target Segment; Secondary Target Segment; Non-target Segment; Core JTBD; Existing Solution / Substitute; Switching Barrier
Scenario model:

`Domain → Task → Environment → Constraint → Failure Cost`

Include Space, Activity, Duration, Environment, Interaction Type, Network/Power conditions, accessibility/human factors, and recovery options when material. Overlay buyer-specific organizational requirements only when relevant and evidenced: e.g., admin controls and integration for Enterprise; jurisdiction-specific procurement and data handling for Government; verifiable defense-sector authorization and reliability constraints for Defense. Do not infer actual adoption or certification from product capability.
### Five-track evaluation
1. **Standardized Performance** — comparable measurements under controlled conditions.
2. **Scenario Experience** — real environmental conditions and practical constraints.
3. **Workflow Outcome** — whether the complete task is successfully finished.
4. **Stress / Failure Behavior** — what breaks, when, and how recovery works.
5. **Long-term / Lifecycle** — reliability, degradation, maintenance, software support, service, warranty, TCO.

Remote Research Mode maps public evidence to these tracks. It does not convert public evidence into hands-on testing.
### Workflow metrics
When workflow matters, measure or infer with evidence:
- task completion rate; time to completion; number of steps; context switching; manual intervention; failure rate; recovery time; rework; compatibility; output quality; reliability across repeated use
### Issue Log
Issue Log: Issue ID; Product / SKU / Version; Scenario; Trigger; Symptom; Reproduction status; Severity; Workaround / Recovery; Current Status.
### Failure modes
Critical failures are first-class Findings: record trigger, affected segment/scenario, severity, reproducibility, workaround/recovery, data-loss/safety/business impact and version. Never average away task-blocking failures.
### Long-term and lifecycle
Consider when material:
- battery / component degradation; repairability; consumables; warranty; service availability; firmware/app support; subscription dependence; cloud dependence; data portability; compatibility drift; resale / residual value
- total cost of ownership
### Test Bench
Record Test Bench Version and preserve:
- protocol; device / SKU; firmware / software; date; environment; equipment; settings; run count; variance; exceptions
Change the Test Bench version when method changes could alter comparability.
## Actor-level competitor intelligence: C0–C8
### Objective and boundaries
`Competitor Intelligence` studies **a competing company, brand, or business unit** as a strategic actor. It is not a multi-product review and is not a neutral company encyclopedia. Answer: **what competitive position the actor holds, which mechanisms produce it, whether those mechanisms endure, how the actor can respond, and what actions the evidence supports**.

A bare unambiguous company, brand, or business-unit name defaults to `Competitor Intelligence`, `Highest / Strategic Deep Research`, and `Remote` evidence mode. Scope is the identified entity and its materially relevant businesses, regions, value chain, and competitor set—not every entity sharing the name. If the user's own enterprise is unknown, evaluate relative to defined industry actors or a transparent reference position; never invent the user's capabilities or strategy.

`Product Competitive Analysis` remains a distinct product-level Intent; product evidence is imported selectively to verify the actor's capabilities, revenue mechanisms, customer outcomes, and competitive position. `Investment Due Diligence` is a separate decision Intent and is **not automatically activated** by a company name. Commercial-diligence methods can be applied as a validation overlay without claiming to have completed transaction due diligence.
### Entity identification and competitive reference
Before collecting strategic claims:
1. Resolve the requested subject: `Company`, `Brand`, or `Business Unit`; identify official name, aliases, region, relevant business, and applicable research date.
2. Build an **entity boundary map** distinguishing legal operating entity, listed issuer, holding group, subsidiary, product brand, owner of IP, manufacturer, sales/distribution entity, and business unit where material. Capture ownership/control **only at the evidence-supported date and level**. A trade name is not automatically a legal entity.
3. Resolve group versus subsidiary financial reporting boundaries and relevant markets. Do not attribute parent-group financials or patents to a brand or business unit without defensible scope.
4. Establish the competitor's role relative to a specific `Reference Actor`, customer job, geography, segment, and buying decision. The reference actor may be an evidenced named company, a representative industry archetype, or `Unknown`.
5. Preserve unknown ultimate-control, private-company revenue, customer, and supplier arrangements; do not infer undisclosed beneficial ownership or hidden contracts.
For an ambiguous short name, use available context and reliable external identity signals. Clarify only when an unresolved identity would materially change the report. Record the decision in `DecisionBrief.scope` and the `EntityRecord` described in `references/output-contract.md`.
### Mandatory analytical domains
At Highest depth, **screen and process every domain below** to terminal `Resolved`, `Limited Evidence`, `Unknown`, `Unavailable`, or `Not Applicable` with an explicit structural reason for the last status. These are subject-specific research domains; **the product-level mandatory domains are not automatically imposed on a company report**.
| Domain | Core question |
|---|---|
| Entity & control boundary | Which entity actually owns, develops, sells, and controls the relevant business? |
| History & strategic evolution | What observable pivots, milestones, strategic choices, and reversals occurred? |
| Business and brand portfolio | Which brands, lines, services, geographies, and segments matter to the competitive position? |
| Customers, buyers & JTBD | Who buys, chooses, uses, renews, and switches, and why? |
| Market position & rivalry | What is the comparable competitive position against relevant actors and substitutes? |
| Commercial model & monetization | Where is value created, delivered, captured, retained, and lost? |
| Financial & growth quality | What reported or credibly inferred growth, margin, cash, and sustainability signals exist? |
| Product / technology & IP | Which demonstrated capabilities explain outcomes; what depends on licenses or partners? |
| Operations & supply chain | Can the actor scale, fulfill, maintain quality, and absorb shocks? |
| Channels, GTM & brand | How are customers acquired, converted, supported, and retained; what is actually established by attributed public social and advertising activity? |
| Organization & talent | Which observable management, hiring, capability, concentration and staffing-demand signals matter, and which are only vacancy or profile claims? |
| Capital, ownership & partnerships | Which financing and external relationships constrain or enable strategy? |
| Regulation, legal & security | Which material constraints or public risk signals affect continuity or market access? |
| Defensibility & replication | Which advantages are valuable, durable, difficult to replicate, and economically relevant? |
| Strategic moves & scenarios | Which actions are observed, which are hypotheses, and which would change the balance? |
| Threat, opportunity & response | What changes for the reference actor and what decision or resources are justified? |
Financial detail, operational costs, margins, private contracts, and internal performance may remain `Unknown` in Remote mode; breadth completion does not license speculation.

### Workforce, hiring and public-market signal analysis

Apply the source route in `references/classification-routing.md` at **C3 acquisition**, **C4 validation** and **C5 interpretation**. This is an evidence subprotocol under the existing `Organization & talent` and `Channels, GTM & brand` mandatory domains, not an additional C-phase or a requirement to visit all platforms. For Product P8, Category/Industry and D3 People/Technology/Commercial reviews, cross-call only the parts that could change an in-scope claim.

**A. Hiring and professional-network signals**

1. **Frame a falsifiable question.** Examples: Is the actor signaling demand for embedded AI engineers in a named location? Is there evidence of a sales-market expansion? Which technical stack is advertised? Avoid starting with an assumed growth or restructuring narrative.
2. **Choose and acquire.** Start with the original employer careers site and attributed employer announcements, then use accessible LinkedIn, 猎聘 (Liepin), 前程无忧 (51job), 智联招聘 (Zhaopin), BOSS直聘 (BOSS Zhipin), or comparable public listings when they add coverage. Treat 脉脉 (Maimai) as a possible public discussion/recruiting signal with a distinct, often unverified authorship profile; never assume full or authenticated data access.
3. **Identify the accountable entity.** Match legal employer, brand, business unit, city/country, agency or third-party recruiter, and role function. Job-board names and brand names are not reliable ownership evidence by themselves.
4. **Capture the observed posting.** Original URL/job or requisition ID, title, function, level where explicit, public requirements/skills, employment and work location, displayed salary range plus currency/pay period where present, original post/update date, observation date, visible vacancy status, and platform/access limits. Preserve the exact source context; do not invent missing data.
5. **Normalize and de-duplicate.** Detect mirrors across job boards, recruiter syndication, reposts, near-identical adverts, re-opened requisitions, contractor vs employee roles and outdated pages. Store distinct observed postings without counting them as independent hiring decisions or actual filled positions.
6. **Test the capability thesis.** Compare role/skill/location/time patterns against independent launches, customer contracts, regulatory filings, published technical work, procurement, facility evidence or management disclosures when feasible. Check alternatives: replacement hiring, evergreen vacancies, agency pooling, exploratory recruiting, skill taxonomy drift, canceled plans and posting backlog.
7. **State only supported outcomes.** `Advertised Demand` may be supported by a specific posting; `Hiring Completed`, `Net Headcount Change`, `New Team Created`, `Budget Approved`, `Delivery Capability` and `Organizational Restructuring` each need their own evidence. Published salary is a displayed offer range, not actual compensation or verified labor cost. Avoid inferring an individual's employment, reporting line or departure from an old profile alone.

**B. Social and go-to-market signals**

1. Identify the business claim: official positioning, announced distribution, public campaign presence, community discussion, or measurable business outcomes. Do not substitute social metrics for customer economics.
2. Collect only permitted public content from attributable Facebook / LinkedIn company pages and relevant, genuinely accessible ad disclosures; distinguish verified corporate account, employee personal account, fan/community page, sponsored content and user report. Preserve content URL/identifier, platform, publisher, post or ad date, observation date, geography and campaign/product scope where disclosed.
3. Separate `Corporate Statement`, `Ad/Campaign Presence`, `Public Engagement`, `Customer Report`, and independently `Verified Business Outcome`. A Facebook post may establish what the brand said; a public advertisement may establish that a creative was displayed or listed; neither establishes spend, targeting effectiveness, CAC, conversion, incremental sales, retention, ROAS or market share.
4. Normalize platform-specific metrics before comparison and record sampling/visibility limitations. Followers, reactions, comments, ad counts and impressions (when actually disclosed) have different denominators; do not compare across platforms without an explicit method. Detect reposts, bots/incentives, deleted content, recency, regional language and selection effects.
5. Test strategic interpretations against independent product releases, distribution records, customer evidence, filings, financial reports or dated partner confirmations. Competing explanations include a routine campaign, seasonal hiring, page/account ownership ambiguity and marketing claims unconnected to operational execution.

**Decision and reporting rule:** Use a small set of traceable, material signals to explain `Observed Signal → Candidate Capability / GTM Hypothesis → Independent Check → Alternative Explanation → Confidence → Strategic Impact / Revalidation Trigger`. If no relevant source can be accessed, close the applicable ResearchItem as `Limited Evidence`, `Unknown` or `Unavailable`; do **not** label a company as not hiring, inactive on social media, or lacking capabilities. Link supported signals to `SourceRecord`, `EvidenceRecord`, `FindingRecord` and optional domain working records defined in `references/output-contract.md`.
### Social, community, marketplace and DTC evidence subprotocol
**Platform Retrieval Coverage Register is a required investigative artifact**, not an optional account list, where channels can inform a material research domain. Apply at P2/P5/P8, C3–C5, market/comparison studies and relevant D-series reviews. Route through `classification-routing.md` for geography, platform index, identity and access rules; only actor-appropriate platforms enter the must-attempt set.

**R0 — Coverage plan:** Resolve formal entity, brand, aliases, local scripts, exact product/SKU, dates, customer region, industry and target markets. Build a platform-by-market matrix: primary social/content, public community/reviews, major retail/social commerce, owned DTC and relevant regional/vertical/B2B/digital channels. Use official outbound links plus platform-native and search-index discovery. Classify `Primary`, `Secondary` or `Out of scope`; record why.
**R1 — Execute discovery/retrieval:** Actually attempt relevant Primary platforms and material Secondary sources; use localized combinations of brand/product, official account/store, review, price, seller, sales indicator and competitor. Check current plus consequential historical posts/listings. A skipped or inaccessible platform needs an explicit reason; an indexed snippet is not a completed native verification. Expand for contrary user reports and peer alternatives.
**R2 — Capture attribution:** Resolve official/linked brand accounts, authorized retailer, marketplace seller-of-record, creator/affiliate and independent user community. Preserve account/shop URL, post/listing ID, access method, query/date, region/language, product generation, observed claims, disclosed sponsorship and permissions.
**R3 — Extract comparable evidence:** Social: publishing/action, creative, organic/paid/affiliate, timestamp and audience/metric definition. Community: original user experience, version, duplicate thread, reviewer sampling and purchase corroboration. Retail: SKU/bundle/condition, offer, price/coupon, tax/shipping, merchant, stock terms, returns and fulfillment; use the S-series for sales metrics.
**R4 — Validate before inference:** De-duplicate copied posts, syndicated reviews, cross-listed stores and independently unverified quotes. Confirm native sources, entity relationships, meaningful time windows and alternative explanations. `Presence ≠ Reach ≠ Demand ≠ Orders ≠ Revenue ≠ Profit`; no inference of market share or retention from engagement, review counts, rankings or sales badges alone.
**R5 — Expand and close:** Seek material peers/regions, counterexamples and additional independent original evidence until primary platform attempts are accounted for and further obtainable evidence is unlikely to change a decision. Preserve per-platform states `Screened Only / Retrieval Attempted / Observed Source / Attribution Verified`, not substitutes for Coverage Status. `No public result`, `blocked`, `not applicable` and `not searched` are separate. Report material omissions and remaining unanswered questions.

**Channel implications:** Attribute verified signals to brand messaging, product education, discovery/acquisition, commerce/fulfillment, DTC dependence, retention, community/VoC or B2B/developer capability **after retrieval**. Functions explain why evidence matters; they do not justify skipping a relevant platform. Benchmark actors only on matched region, time, SKU and exposure/access conditions; unequal visibility is not automatically inferior execution.
### Commerce Sales Intelligence — cross-cutting execution protocol

This is a **sales-evidence extension** of the existing commerce/channel investigation, not a new primary research mode, a requirement to exhaust every marketplace, or a representation of connected seller credentials. Apply it to Product P2/P6–P8, Actor C3–C6, relevant Market/Comparative work and DD D2–D4 when sales, market traction, channel concentration, or commercial economics are decision-relevant. Follow source-family selection in `references/classification-routing.md` and store results using the existing eight strict record types plus an optional `CommerceSalesMetricRecord`.

**S0 — Define the claim and the economic unit.** State the actor/entity and consolidation perimeter, product/generation/SKU/category, customer vs reseller, platform and merchant, country/currency, measurement window, metric requested, and decision threshold. Distinguish seller `sell-in`, marketplace consumer `sell-through`, ordered/paid/shipped/delivered/net units and bookings/GMV/net sales/recognized revenue. If these are unavailable, mark their status explicitly rather than silently substituting reviews or rankings.

**S1 — Choose sources by proof strength and accessibility.** Screen original issuer audited/financial documents, qualified official commerce/retailer disclosures, permitted user-authorized seller or payment/settlement exports, relevant platform product pages and legitimate method-documented third-party analytics. Prioritize fit and primary origin, not provider names. Record `Public`, `Licensed / Subscription`, `Authorized Internal / Data Room`, `Professional Third-party`, or `Unavailable / Unknown` access, actual attempted URLs and dates. Never bypass login, CAPTCHA, API licensing, export controls or privacy restrictions; a missing merchant API or export yields an evidence gap, not a fabricated result.

**S2 — Capture the native observation without upgrading its claim.** For an observable sales badge/count, capture exact listing URL/ID, seller, SKU, local date/time, label and raw string, threshold/rounding, claimed period and any disclosed counter definition. For a filing or authorized transaction dataset, capture issuer/merchant, transaction event basis, period, line item, amount, tax/returns/fee inclusion, units and reconciliation status. For third-party estimates, preserve provider, as-of period, modeled target, input origin, coverage/sample, assumptions, uncertainty and documented limitations. Screenshots or snippets alone do not upgrade authenticity, completeness or authorization.

**S3 — Assign an explicit evidence class.**

| Class | Minimum defensible criterion | Permitted wording |
|---|---|---|
| `Reconciled Actual` | Authorized transaction/settlement evidence or properly reconciled independent/audited records with a clear seller, product, time, gross-to-net and returns basis | `Verified for the specified account/entity, period and definition`; not automatically audited enterprise revenue or complete market sales |
| `Officially Reported` | Original dated company, exchange, public platform or merchant disclosure with a traceable metric and reporting boundary, without independently reconciled transaction records | `Company/platform-reported` as specified, not independently verified sell-through |
| `Method-disclosed Estimate` | Lawfully sourced published/authorized third-party model with transparent metric, inputs, date, coverage and uncertainty | `Estimated`, explicitly state scenarios/range and estimation method |
| `Observed Sales Indicator` | Native visible sold-label, rank, review count, order badge or storefront activity with incomplete counter semantics | `Displayed/observed signal`; no asserted transaction count or revenue |
| `Unknown` | No accessible defensible metric or irreconcilable definition, seller, vintage or permission gaps | `Unknown / Not Estimable`, with the missing verification test |

**S4 — Normalize before calculation.** Use a comparable key: `legal actor + channel operator + seller + marketplace + geography + exact SKU/condition/bundle + metric definition + date basis + measurement interval + currency/tax/discount/refund status`. Keep listing observation date separate from the period measured and source publication date. Convert FX only with sourced rates and dated methods; do not mix list price, realized ASP, subsidized price or returns-adjusted cash receipts. Compute AOV/ASP, growth, net units or channel mix only when numerator, denominator and adjustments are sourced and consistent. An interpolated or modeled value remains estimated, even if arithmetic is correct.

**S5 — Reconcile cross-platform and accounting boundaries.** Identify duplicate sellers/listings, the same units passing through wholesale and end-customer channels, drop-shipping, affiliate commissions, syndicated rankings, multi-store fulfillment, cancelled/returned orders, platform refunds and reseller stock. A marketplace SKU appearing on several storefronts does not add new sales automatically. Distinguish GMV versus merchant net sales, issuer recognized revenue, payouts/cash, gross versus net agent/principal presentation, reporting entity versus brand and sell-in versus sell-through. Refuse market share or platform-wide total claims without defensible common-market denominators and coverage.

**S6 — Estimate only when identifiable and auditable.** Require an explicit question, transparent quantitative model, source-backed parameters, observation unit, time and market alignment, credible validation/calibration against independent actuals, interval or sensitivity range and counter-model. Do not use an arbitrary `review-to-sales`, `rank-to-sales`, `follower-to-order`, `listing price × badge` or `traffic × conversion` factor. Without support, output a qualitative demand indicator and `Not Estimable / Limited Evidence`, not a point estimate or fabricated confidence interval. For a model sourced from one opaque commercial vendor, state the single-model dependence.

**S7 — Interpret commercial meaning and alternatives.** Ask whether the evidence demonstrates channel penetration, sustained sell-through, price realization, promotional dependence, repeat purchasing, geographic expansion, competitive share or economically attractive revenue. Challenge temporary campaigns, seasonal base effects, returns, channel stuffing, distributor inventory, paid/affiliate promotion, duplicate shops, reporting changes and missing data. Seller-level records do not establish group-wide profitability or brand-wide growth absent a documented bridge.

**S8 — Record and finish honestly.** Attach optional `CommerceSalesMetricRecord` rows to `CommerceSignalRecord` or `PlatformPresenceRecord` where applicable and always link to `SourceRecord` / `EvidenceRecord`; promote material interpretations to Finding IDs with counter-evidence and falsifiers. Show the exact metric, value/range **or `Unknown`**, class, period, region, seller/entity, method, comparable peer scope and access limitations. Log selected, attempted and omitted sources separately. Stop when credible additional obtainable evidence would not change the decision, or conclude a clearly bounded evidence gap.

**Minimum useful output for sales-oriented requests:** A platform/merchant-by-product sales-evidence matrix with separate columns for observed indicators, reported/verified sales metrics, model-based estimates, quality tier, date/period, and decision-relevant gaps. Do not generate empty synthetic rows, report absolute numbers without sources, or imply that marketplace seller-center sales tools are automatically connected.

### Competitor comparison and threat assessment
Build competitor tiers according to relevant **competitive interaction**, not corporate size alone: direct player in the same job/segment, substitute, platform/ecosystem controller, upstream enabler, adjacent entrant, emerging challenger, and strategic benchmark. For each actor record `Reason for Inclusion` and comparison unit.

Normalize `Company / Brand / Business Unit → Consolidation Scope → Geography → Period → Segment → Revenue Basis → Currency → Source Method`; distinguish sales, shipments, GMV, users, ARR, market share and valuation. Do not rank noncomparable figures.

A strong claim follows:

`Observable Move or Outcome → Verified Mechanism → Relative Capability → Sustainability / Replication Cost → Competitive Effect → Conditional Response`.

Threat assessment must show: `Reference Actor / Target Segment / Exposure / Time Horizon / Observable Signals / Capability & Incentives / Counter-evidence / Confidence / Action Trigger`. If own-firm capabilities are unavailable, express **industry-facing threat scenarios**, not individualized countermeasures.
### Commercial due diligence overlay
Borrow the falsification and verification discipline of commercial due diligence (as defined in the due-diligence section of this SOP):
- Articulate an evidence-testable competitive thesis and credible alternative explanations.
- Test claimed growth against customer adoption, retention, channel behavior, revenue mix and available cash/economic signals.
- Trace performance back to drivers and ask whether the drivers are durable, replicable, subsidized or contingent on a partner.
- Examine concentration, customer/supplier dependence, platform risk, geographic and regulatory exposure.
- Elevate material adverse signals; distinguish `Material Red Flag` from actual proven misconduct and from a `Decision Blocker` in the user's decision process.
- Record the conditions and **new evidence** that would strengthen, weaken or falsify the thesis.
Do **not** assert that financial, legal, tax, operational or technology *transaction* diligence is complete when private records, management access, independent testing or qualified specialists were not available.
### Output and completion gates
Deliver a finding-led `Competitor Intelligence Report` with entity identity and boundary, cutoff, strategic thesis, relevant portfolio/market reference, source-backed capability/competitive assessments, material risks and opposing evidence, conditional response options, and thesis revalidation triggers. Include a complete source register and status for every Highest-depth domain. Company/brand visuals are optional when officially available and relevant; **product hero images and specification matrices are not mandatory** for this Intent unless a product sub-analysis warrants them.

Finish only after subject-specific breadth is terminal, material company/brand comparisons are normalized or explicitly limited, and added evidence is unlikely to change conclusions, confidence, trade-offs, or recommended action. Leave data-room-dependent items explicit as `Unknown` / `Unavailable`, not as silently assumed failures or completed diligence.
## Investment due diligence: D0–D8
### Purpose and activation
`Investment Due Diligence` is an explicit investment, acquisition, minority investment, financing, or transaction evaluation Intent. It asks: **what must be true to justify the decision, what evidence verifies or falsifies it, what downside is possible, and what conditions could change the recommendation?**

Do not start a transaction diligence report merely because the input is a company or brand name. By default, bare company/brand names use `Competitor Intelligence`; its commercial verification may borrow due-diligence **methods** without claiming the transaction due diligence has been completed.

The review is analytical, not an audit opinion, legal opinion, tax certification, formal securities valuation, or assurance that every liability has been identified. Specialists and consent may be required for a real transaction.
### Access levels and evidence boundary
Record `Evidence Mode` (Remote / Hands-on / Internal) separately from `Evidence Access`: `Public`, `Licensed / Subscription`, `Authorized Internal / Data Room`, `Professional Third-party`, or `Unavailable / Unknown`. The labels describe **actually available** evidence, not entitlement to obtain it. Public-source investigation must be identified as `Public-source Due Diligence` / **preliminary diligence**.
| Mode / access | Appropriate work | What cannot be concluded automatically |
|---|---|---|
| Public records and published reports | Market/customer/competition, disclosed financials, registries, public legal/IP/risk signals | Complete private financials, undisclosed contracts, cash balances, hidden liabilities |
| Licensed database / authorized data | Use only legally accessible returned fields, subject to licensing and vintage | Database entries alone do not verify all primary originals |
| Authorized data room / internal | Test financial ledgers, signed contracts, cohorts, source systems, cap table and operating records | Internal disclosures do not by themselves establish independence or completeness |
| Specialist reports / direct testing | Independent accounting, legal, technical, security, operational, and tax checks | Results beyond specialist scope, dates, and sampling |
Never claim private access, use login-bypass/scraping workarounds, or misrepresent an external search as a forensic audit. Flag inaccessible areas with a requested document/verification plan instead of inventing them.
### Investment thesis and review criteria
Construct an `InvestmentThesisRecord` (see `references/output-contract.md`) with: subject boundary, thesis, drivers, assumptions, falsification tests, supporting and counter-evidence, critical unknowns, downside scenario, recommendation threshold and revalidation trigger. Make **decision rights and investment mandate** explicit when given; otherwise `Unknown`.

For each critical claim ask:
1. What specifically must be true and at what time horizon?
2. Which document, ledger, third-party interview, independent measure, or official record would confirm it?
3. Which plausible alternative would produce the same observation?
4. What observation would **falsify** it?
5. Would the claim's failure change valuation, legal ability to transact, cash need, strategy, or decision?
Do not use financing events, hiring advertisements, patent counts, awards, marketing claims or announced client logos as standalone evidence of realized product-market fit, realized revenue, durable moat or collected capital.
### Diligence domains
At Highest depth, screen all domains below. Complete applicable research to a terminal status, preserving `Unknown`, `Unavailable`, and `Limited Evidence` when access is insufficient. `Not Applicable` requires a structural reason. Material deal blockers must remain visible even if numerical scoring is otherwise favorable.
| Domain | Minimum analytical purpose |
|---|---|
| Corporate/ownership/capitalization | Correct entities, shareholders as disclosed, voting/control arrangements where evidenced, options and investment rights |
| Commercial (CDD) | Market boundary, demand, segment economics, competition, customer acquisition, retention and growth drivers |
| Financial (FDD) | Revenue recognition/quality, margins, working capital, cash conversion, debt, liquidity, forecasts and reconciliations |
| Legal (LDD) | Contract rights, IP ownership, litigation, employment, commercial/regulatory liabilities and compliance |
| Tax | Material taxes, exposures, filings and structuring questions when data and expertise permit |
| Technology / cybersecurity | Architecture, maintainability, platform/model/vendor reliance, information security, data rights, IP, technical debt |
| Operations / supply chain | Capacity, quality, supplier/customer concentration, fulfillment, inventory, continuity and cost reliability |
| Management / people | Leadership continuity, key-person exposure, incentives, governance, capability and attrition signals |
| Customer / partner / channel | Verified customer contracts and cohorts, churn, channel economics, platform dependency, concentration |
| Regulatory / ESG / privacy | Relevant licenses, data/privacy and sector-specific environmental/social/regulatory exposure |
| Capital needs / valuation | Runway, future financing, dilution, comparables, DCF/unit economics when inputs allow, exit constraints |
| Integration / execution / exit | Post-transaction dependencies, integration feasibility, execution milestones, exit options and realizable value |
### Nine-phase execution SOP
| Phase | Task | Output |
|---|---|---|
| D0 — Mandate & screen | Define investment decision, asset/entity, stake, geography, horizon, access, completion criteria and investment thesis | DecisionBrief / Thesis Register |
| D1 — Entity & rights | Resolve entity relationships, ownership, control, IP rights, capitalization and deal boundary | Entity/Capitalization Map |
| D2 — Commercial | Verify market/customer demand, competitors, growth mechanisms, WTP and channels | CDD Findings |
| D3 — Functional streams | Execute FDD, LDD, Tax, Tech, ODD, HR and compliance streams as applicable and accessible; public recruitment/social signals may scope requests but never replace employee, payroll, contract or operational verification | Domain Coverage / Requests |
| D4 — Independent corroboration | Compare representations with source systems, filings, clients, suppliers or expert/testing evidence | Evidence / Contradiction Log |
| D5 — Economics & valuation | Reconcile financial quality, cash, working capital, capex, unit economics, projections and assumptions; model evidence-supported scenarios | Financial Bridge / Valuation Ranges if feasible |
| D6 — Risk & remedy | Identify red flags, deal blockers, mitigations, warranties/conditions subject to legal review, and verification needs | Risk Register / Decision Conditions |
| D7 — Decision memo | State Invest / Conditional / Defer / Decline or equivalent only against defined mandate and evidence | Investment Memo + Open Questions |
| D8 — Monitoring | Define thesis invalidation signals, verification deadlines and post-decision monitoring plan | Revalidation Plan |
These phases may overlap or reorder by transaction type. An unfulfilled documentary request is an `Evidence Gap`, not proof of a negative finding. Never infer that the company refused materials unless documented.
### Red flags and decision controls
- `Material Red Flag`: credible signal or unresolved inconsistency with potential material impact. Describe allegation, evidence stage, source and rebuttal; do not convert suspicion into a proven finding.
- `Decision Blocker`: a decision-process condition (e.g., material unresolved ownership rights or financial reconciliation) that prevents a responsible affirmative conclusion at the specified mandate/threshold. It is **not** proof that the company is misconducting or worthless.
- `Deal Breaker`: a verified issue or unacceptable conditional risk that genuinely invalidates a **specified** transaction mandate; not an unqualified label for any negative article.
- `Mitigation`: realistic remedy, required evidence, accountable reviewer, cost, deadline and residual risk where known.
Use scenario thresholds rather than averaged risk scores that can conceal existential losses. A negative search result does not establish an absence of litigation, tax exposure, or liabilities; document jurisdiction and search coverage.
### Valuation and financial quality
Distinguish revenue vs bookings/GMV/ARR, gross vs net sales, contracted vs recognized vs cash-collected revenue, cohort retention vs account count, and acquisition/one-time growth vs organic growth. Evaluate recognized income, receivables, deferred revenue, refunds, related-party transactions, concentration, gross margin, cash burn/working capital, debt and commitments **only with documented inputs**.

Valuation models (DCF, trading/transaction comparables, venture methods, asset approaches) require explicit cash flows, units, time basis, peer comparability, cost of capital/discount and risk assumptions. **Screen first; do not force an estimate or numerical investment return** when reliable data is absent. Show assumptions and decision-changing sensitivity thresholds when feasible. Do not reverse-engineer undocumented margin from revenue, or treat an announced fundraising valuation as a verified current enterprise value.
### Completion and reporting
Produce a finding-led `Investment Due Diligence Report / Investment Memo` with mandate, entity/cap table boundary, scope and access, thesis and counter-thesis, commercial/financial/legal/technical/operational findings, risk register, valuation or explicit `Not Estimable`, investment conditions, missing diligence requests, source register and research cutoff.

A report based only on public information must prominently state **Preliminary / Public-source DD**, with `Unverified` private financials, taxes, contracts, and liabilities as applicable. Never claim `Comprehensive Transaction DD Completed` unless the defined scope, authority, specialists and evidence genuinely support it. If the user asks for an investment recommendation under insufficient evidence, a **conditional or defer** decision can be more defensible than false precision.

Completion follows both subject-specific coverage and depth-saturation gates; inaccessible data gets a terminal limitation status and concrete next verification action. Full disclosure of a gap does not mean that the underlying financial/legal matter has been cleared.
### Revalidation
Preserve `Thesis → Key Evidence → Alternatives / Counter-evidence → Falsifier → Observed Signals → Monitoring Frequency (if separately scheduled) → Next Review Trigger`. A one-time Skill report may suggest monitoring but must not claim it will keep monitoring or schedule itself without explicit user instruction and a supported scheduling mechanism.
## Evidence quality, contradictions, and falsification
### Evidence, confidence and source quality
Distinguish `Fact / Measurement / Observation / Customer Report / Interpretation / Hypothesis`; `Source ≠ Evidence ≠ Finding ≠ Conclusion`. Use `High / Medium / Low / Unknown` Confidence based on directness, primary origin, transparent method, independence, version/SKU/region/scenario fit, reproducibility, freshness, conflicts and interest. Manufacturer claims can confirm official specifications or `Official Targeting`, not independently validated performance, `Verified Adoption`, public-sector/defense certification, or procurement eligibility.
### Provenance, contradictions and validation
Capture `primary_origin / lineage_id / source_independence / directness / freshness / version_fit / scenario_fit / method_quality`. Multiple publications or repeat measurements derived from one origin are not independent evidence dimensions.
For material conflicts create `ContradictionRecord`: claim, opposing Evidence IDs, version/region/scenario/method differences, potential explanation, resolution status, uncertainty and decision impact. Resolve by relevance/method/independence and recency, not citation count.
Triangulate across **vertical** (SKU), **horizontal** (brands), **longitudinal** (generations/time), **scenario** (environments), **method** (different measurement process) and **source** (independent origin) where useful. Require `Measurable → Perceptible → Decision-relevant`; statistical significance alone is not practical relevance.
### Corporate and diligence claim tests
Match legal entity/brand/BU/group reporting boundary, event/effective date, region and operational/accounting metric. Keep event announcement, completed fact, outcome and inference distinct:
- Funding announced ≠ cash received; patent filed ≠ granted/enforceable or commercialized; hiring notice/profile ≠ filled role/headcount/team capability; registry ≠ full beneficial ownership/control.
- Customer logo ≠ retained paying adoption; public social engagement/ad presence ≠ customer acquisition, spend or ROI; marketplace listing/badge/review ≠ realized sales; allegation ≠ proven misconduct; negative public search ≠ absence of liabilities.
Every consequential claim requires `Supporting Evidence → Independent Challenge → Alternatives → Falsifier → Decision Impact → Revalidation Trigger`. Label credible material concern `Material Red Flag`, unresolved decision threshold `Decision Blocker`, verified deal-incompatible risk `Deal Breaker` only for the explicit mandate. Do not confuse these with Coverage Status or characterize inaccessible data rooms as reviewed.
### Evidence sufficiency
Use `Claim Materiality × Evidence Quality × Independence × Applicability`, independent of Execution Priority. Seek at least two independent evidence dimensions for material Findings where feasible; otherwise label `Single-source / Limited Evidence` and lower Confidence. Preserve important but insufficient signals as hypotheses, not conclusions.
## VoC ingestion and bias control
### Purpose
VoC discovers recurring topics, failure modes, long-term issues, scenario-specific problems, version-specific problems, unmet needs, and language used by customers. Public employee/professional discussion about an employer is **not** product VoC unless it contains a verifiable customer/user experience; route employment-related material to the workforce-signal protocol, retaining distinct authorship, privacy and representativeness limitations.

VoC does **not** directly establish population incidence or market share.
### RAW → CLEAN → GOLD
#### RAW
Preserve immutable source data where available:
- raw text; platform; URL / source ID; author / author hash; timestamp; SKU / product; rating; collection time
Never rewrite RAW.
#### CLEAN
Apply:
1. schema normalization
2. time normalization
3. product / SKU resolution
4. exact duplicate removal
5. near-duplicate detection
6. spam / promotion flagging
7. quoted/reposted content detection
8. language normalization only when required for analysis
9. platform and version tagging
10. buyer / end-user role, target market, and industry tagging only when supported by the source; otherwise `Unknown`
Do not delete outliers merely because they are inconvenient. Flag them.
#### GOLD
Create analysis-ready units with:
- aspect; sentiment / polarity where useful; scenario; failure mode; severity; product/version context; unique-author count; mention count; evidence confidence
### Deduplication
`Mention Count ≠ Unique Author Count`.

Multiple reposts, quote chains, cross-posts, affiliate copies, and repeated support tickets may share one underlying experience. Preserve lineage when possible.
### Bias and sampling
Disclose when material:
- platform selection bias; reviewer self-selection; incentive / affiliate bias; launch-period skew; survivor bias; language / region bias; version / firmware drift; star-rating extremity bias; unavailable deleted content
Stratify by platform before pooling when platform populations differ materially. Do not pool practitioner feedback, individual purchases, enterprise administrator accounts, and institutional procurement reports as if they described the same buyer population. User reviews alone generally cannot prove the identity of a purchasing organization or official sector adoption.
### Aspect analysis
Prefer aspect-level analysis over one global sentiment score. Common aspects:
- quality / performance; setup; reliability; software; AI; ecosystem; support; pricing; workflow; durability
### Correct inference chain
Use:

`VoC → Pattern → Hypothesis → Test / Evidence Priority → Finding`

Do not use:

`VoC → Market Incidence Claim`

unless a representative dataset supports that inference.
### Human QA
For consequential cleaned datasets, inspect samples before and after cleaning, compare distribution shifts, document exclusion rules, and retain enough provenance to reproduce the cleaning decision.
## Market and economics investigation
### Market definition
Define before sizing:
- category boundary; unit of analysis; geography; time period; customer segment and evidenced target market (`Consumer` / `Professional` / `Enterprise` / `Government` / `Defense`)
- economic buyer vs end user and transaction model (`B2C` / `B2B` / `B2G` where applicable); industry vertical and public / defense institutional scope where relevant; shipment / sell-in / sell-through / installed base
- revenue / GMV / bookings / ARR where applicable; hardware-only vs service-inclusive scope
Do not combine sources with materially different definitions without reconciliation. `Professional` can overlap with individual consumer purchases or institutional deployment; `Government` and `Defense` can overlap. Do not sum overlapping market segments as if they were disjoint TAM components. Treat unverified sector applicability as an opportunity hypothesis rather than observed demand.
### Market sizing
Use, where evidence permits:
- Top-down; Bottom-up; Proxy / triangulation
Prefer at least two approaches for material market-size claims.

Normalize:
- definition; geography; year; currency; nominal vs real values when material; volume vs revenue; channel basis
If only one opaque consulting estimate exists, report it as one estimate rather than “the market size.”
### Price and willingness to pay
Distinguish:
- MSRP; dated region/SKU/merchant-specific street price; public promotional/coupon price and eligibility; taxes, shipping, returns, subscription / service cost; bundle economics; procurement, implementation, and ongoing compliance / administration costs where applicable; switching cost. An observed offer is not a verified transacted price or representative ASP.
WTP evidence can come from observed purchase behavior, price ladders, conjoint/survey evidence, churn/retention, attach rates, or credible segment behavior. Distinguish user preference from budget holder approval in institutional purchases. A procurement list price or vendor sector page does not establish executed contract price, purchasing volume, or adoption. Do not infer precise WTP from list price alone.
### Revenue / profit pools
When evidence allows, map where value is captured across hardware, software, subscription, services, accessories, channel, advertising, data, financing, or ecosystem effects.

Do not fabricate gross margin or profit pool when only revenue is known.
### TCO and switching cost
TCO may include:
- purchase price; subscription; accessories; consumables; service / repair; downtime; migration; training; integration; replacement cycle
Switching cost can be financial, workflow, data, social, learning, integration, or ecosystem-based.
### Business model
Analyze:
- value creation; delivery; monetization; recurring vs one-time revenue; service dependency; channel economics; retention / expansion logic; ecosystem cross-subsidy
Business Model Canvas may be used when it adds explanatory value; it is not mandatory as a report chapter.
### Unit economics
Only calculate when inputs are sufficiently supported. Potential components:
- ASP / ARPU; gross margin; CAC; contribution margin; retention / churn; attach rate; service cost; payback; LTV
If data is missing, mark Unknown instead of reverse-engineering pseudo-precision.
### Financial diligence and value quality
For competitor-actor analysis, first define the legal/reporting perimeter and source period: consolidated group vs subsidiary/BU vs brand. A privately held firm's unreported figures are `Unknown`; company funding, app rankings, or website traffic do not establish revenue, gross margin, cash burn, or profit.

When disclosed or authorized evidence permits, reconcile:
- Bookings / GMV / contracted ARR / recognized revenue / cash collected / one-off vs recurring items.
- Revenue quality: organic vs inorganic growth, refunds, concentration, related-party transactions, deferred revenue and retention/cohort evidence.
- EBITDA/profit versus operating cash flow, receivables/working capital, capex, recurring service costs, debt and liquidity.
- Software AI unit economics: inference/training costs, cloud/vendor dependencies, gross margin by product/tier, variable support and customer acquisition.
- Hardware economics: production yield, BOM and fulfillment when evidenced, inventory/warranty/returns, channel deductions, accessory and subscription attach.
Do not perform a numerical bridge when the required records are unavailable. Label sourced figures as `Reported`, `Verified / Reconciled`, `Third-party Estimate`, or `Scenario Assumption` and specify accounting/measurement basis. Commercial due diligence asks whether the demand and growth drivers are **durable and economically viable**, not merely whether growth is reported.
### Valuation conditions
Run valuation **only for explicit investment/transaction decisions or when the strategic question genuinely needs it**. Screen suitable methods—comparables, DCF, venture/transaction or asset-based—and demand comparable entity perimeter, periods, currencies, normalized multiples, forecasts/cash flows and assumptions. Never present a funding headline or one opaque private-company estimate as current enterprise value. If inputs are insufficient, return `Not Estimable / Limited Evidence` with required verification items rather than a fabricated number. Apply the relevant subsection of this SOP.
### Sensitivity
For uncertain commercial conclusions, vary the assumptions most capable of changing the decision. Show breakpoints rather than one deterministic forecast.
## Strategic tool screening and execution
### Domain vs tool rule
At Highest depth, **all domains mandatory in the selected Product / Competitor Intelligence / Due Diligence protocol are mandatory**. Product-level domains do not automatically transfer as a fixed checklist to companies or brands.

Strategic frameworks are tools. Do not mechanically generate every framework as a report section.

Use two stages:
1. **Framework Screening — mandatory**
2. **Framework Execution — conditional on applicability and minimum evidence**
Record `screening_status` as `Execute`, `Not Applicable`, `Unknown`, or `Limited Evidence`, with a reason. For `Execute`, document whether execution completed and cite its input Findings/Evidence; do not confuse selection for execution with evidence-backed completion.
### Framework screening
For each tool ask:
- What decision question would this tool answer?; What is the correct unit of analysis?; Is the required evidence available and comparable?; Would the result materially improve explanation, decision, or resource allocation?
- Is another tool already answering the same question more directly?
### Evidence preconditions
| Tool | Minimum evidence / setup | Invalid use |
|---|---|---|
| PESTEL | defined geography/time + external driver evidence + exposure mechanism | generic macro checklist with no product/market linkage |
| Five Forces | defined industry boundary, geography, time, value-chain position | mixing different industries or using unsupported force ratings |
| SWOT/TOWS | prior Findings with evidence IDs | brainstorming S/W/O/T before research |
| BCG | explicit business/product unit + comparable relative share + market growth | assigning Star/Cow/etc without share/growth evidence |
| GE-McKinsey | defined attractiveness and competitive-strength dimensions with evidence | arbitrary weighted scoring presented as fact |
| Value Chain | activities and value/cost/capability evidence | generic company-process list |
| VRIO/RBV | explicit resource/capability unit | treating “brand/company” as one undifferentiated VRIO resource |
| Ansoff | current product/market baseline + feasible growth options | listing four quadrants without option evidence |
| STP | meaningful segments + targeting basis + positioning evidence | demographic labels without different needs/behavior |
| Strategy Canvas | comparable factors target segments actually value | feature-count radar masquerading as value curve |
| Kano | credible demand evidence and attribute framing | labeling attributes from analyst intuition alone |
| JTBD | situation, motivation/progress, existing solution, switching forces | generic persona description |
| Business Model Canvas | business model materially explains value capture/delivery | template filling without evidence |
| 4P / 7P | GTM/marketing/service decision is material | generic marketing checklist |
| Scenario / Sensitivity | uncertain variables with decision-changing ranges | arbitrary best/base/worst narratives |
| Competitive Response / Game Theory | identifiable actors, incentives, feasible responses | speculative “competitor will…” storytelling |
| Commercial Due Diligence / Thesis Test | defined customer/market claim, independent evidence dimensions, alternative explanation and falsifier | reciting company marketing or financing as proof of demand |
| Financial Quality / Cash Conversion | matching reporting entity/period and disclosed or authorized financial statements / cash data | deriving margins or runway from valuation headlines |
| Corporate / Ownership Map | verifiable names, registry/filings and date-specific relationships | treating the brand and parent as the same entity or inferring hidden control |
| Valuation Model | mandate, comparable perimeter, defensible inputs and sensitivity assumptions | numerical precision without actual revenue/cash/market basis |
| Risk / Decision Blocker Review | clear mandate, material risk signals, evidence and verification threshold | conflating allegation, evidence gap and proven breach |
### Tool protocols
Use tools only with the minimum evidence in the screening table; every output traces to Findings/Evidence and explicitly states limits.
- **PESTEL:** `Driver → Evidence → Mechanism → Exposure → Strategic Implication` for a defined place/time.
- **Five Forces:** define industry/value-chain boundary; test rivalry, entrants, substitutes, buyer and supplier power.
- **SWOT / TOWS:** late synthesis of supported Finding IDs; translate SO/ST/WO/WT into conditional actions.
- **BCG / GE-McKinsey:** require defensible portfolio unit, share/growth or attractiveness/strength inputs; otherwise `Limited Evidence` / `Not Applicable`.
- **Value Chain:** link value creation/capture/loss/dependence to evidenced activities and costs.
- **VRIO / RBV:** evaluate a specific resource (`Valuable → Rare → Inimitable → Organized`) and defensibility; no generic company-wide VRIO label.
- **Ansoff:** option, market/product baseline, required capability, economics and risk.
- **STP:** segment by need, decision authority, job, WTP and buying path; separate official targeting, verified adoption and potential fit; do not turn Consumer/Professional/Enterprise/Government/Defense into exclusive or automatically evidenced markets.
- **Strategy Canvas / Kano / JTBD:** grounded buyer value/attribute evidence, not decorative feature scoring.
- **Scenario / Sensitivity:** vary decision-changing variables and report thresholds.
- **Competitive Response:** model specific actor incentives, constraints, alternatives and triggers; speculative branches remain hypotheses.
### Company capability, supply chain, and capital
#### Company capability
Use:

`Background / Resource Signal → Capability Hypothesis → Product Evidence → Replication Difficulty → Strategic Implication`

Analyze organization, R&D, IP, brand, channel, GTM, software/data capability, manufacturing/operations, and partner network only to the extent they explain observable product or market outcomes. Team biography, financing, naming, hiring listings, professional profiles or corporate social claims cannot independently prove capability. For relevant hiring/social signals, apply the bounded protocol under Actor-level competitor intelligence; record unmet corroboration rather than upgrading signals into outcomes.
#### Supply chain and operations
When evidence permits, assess:
- Commodity / Customized / Proprietary components; BOM / cost structure signals; ODM / OEM / in-house boundary; tooling; yield; capacity; lead time; supplier concentration; geographic concentration; certification / regulatory dependency
- logistics / inventory exposure; replication difficulty; operational bottlenecks
If evidence is unavailable, mark Unknown / Limited Evidence rather than inferring supplier economics from retail price.
#### Capital / financing / strategic transactions
At Highest depth, screen funding, M&A, strategic investment, capital intensity, and financing dependence when they can alter competitive endurance, supply, channel expansion, R&D capacity, or strategic options. Financing events are context signals, not proof of product-market fit or durable advantage.
### Competitor thesis and diligence screening
For `Competitor Intelligence`, screen commercial durability, customer concentration, funding/runway dependence, organizational execution, technology/IP ownership, platform reliance, regulatory barriers and company/brand scope, then apply only supported tests. Run the sequence:

`Competitive Thesis → Observable Signals → Alternative Explanations → Independent Tests → Replicability / Sustainability → Counter-move Scenarios → Conditional Response`.

For explicit `Investment Due Diligence`, use `Investment Thesis → CDD / FDD / LDD / Tech / ODD / Tax / HR Screens → Red Flags & Blockers → Value / Cash Sensitivity → Conditional Investment Decision` with evidence sufficiency per stream. No framework result can replace missing signed contracts, ledgers or specialist review. Apply the relevant C- and D-series above.
### Synthesis order
A useful strategic chain is:

For product research: `External Environment / Industry → Market / Segment → Product / Workflow → Competition → Economics → Capability → Defensibility → Growth / Opportunity → Resource Allocation`.

For actor research: `Entity Boundary → Business / Market & Customer → Competitive Behavior → Commercial/Financial Quality → Resources / Capability → Durable Advantage / Exposure → Scenarios → Response / Resource Allocation`.

For transaction diligence: `Mandate / Thesis → CDD and Specialist Evidence → Economic Quality / Valuation → Risks / Blockers → Conditions → Decision / Revalidation`.

The final report still follows Findings, not framework names.
